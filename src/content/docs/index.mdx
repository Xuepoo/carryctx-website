## What CarryCtx is

<p class="ctx-lede ctx-reveal">
  CarryCtx is the <strong>durable project state and control layer</strong> that sits between your repository and every agent or human working in it. Three ideas define it.
</p>

<div class="ctx-reveal">
<CardGrid>
  <Card title="Durable State" icon="document">
    One SQLite file at `<git-common-dir>/carryctx/state.sqlite`, shared by every linked worktree. Tasks, dependencies, sessions, checkpoints, handoffs, decisions, events, and analytics are queryable rows — not prose an agent must re-parse each session.
  </Card>
  <Card title="Lifecycle" icon="random">
    From `init` and dependency-aware planning through roles and teams, worktree-bound sessions, progress and checkpoints, handoffs and review, to cleanup, reconciliation, and release evidence — one control plane for the full delivery loop.
  </Card>
  <Card title="Portable & Mergeable State" icon="approve-check-circle">
    Fully local and offline by default. No cloud service, account, or network round-trip. Move state with `carryctx export` / `import` (`ctxpack` v2), merge two clones with a semantic three-way merge, and let Git, SSH, or any external transport you choose carry the artifact.
  </Card>
</CardGrid>
</div>

<div class="ctx-reveal">

### What it is not

<CardGrid>
  <Card title="Not an agent harness" icon="error">
    CarryCtx does not launch, schedule, or route agent processes. Your external harness owns execution — CarryCtx persists the coordination state those processes rely on.
  </Card>
  <Card title="Not a Claude Code replacement" icon="error">
    It is agent-agnostic. Claude Code, Codex, OpenCode, Copilot, or a human at a terminal all speak the same CLI and stdio MCP surface.
  </Card>
  <Card title="Not a cloud sync service" icon="error">
    No hosted state, no telemetry, no required account. Portable state travels as a local file you control.
  </Card>
  <Card title="Not a TODO list" icon="error">
    Dependency-gated tasks, CAS-safe claims and handoffs, Git-aware checkpoints, and an append-only event log — richer than any checklist.
  </Card>
</CardGrid>
</div>

## Core Features

  <p class="ctx-lede ctx-reveal">
  CarryCtx manages the lifecycle around software delivery for coding agents and human collaborators. It keeps
  the project contract, plan, dependencies, roles, sessions, progress, review trail, cleanup decisions, and
  release evidence in one local, Git-aware state model.
</p>

<CardGrid stagger>
  <Card title="100% Offline & Local" icon="approve-check-circle">
    State lives at `<git-common-dir>/carryctx/state.sqlite`, shared by linked worktrees. No cloud service, account, or network round-trip is required.
  </Card>
  <Card title="Durable Agent Teams" icon="bars">
    A commander plus role-specialized subagents, persisted like every other fact. Handoffs advance through a state machine with compare-and-swap updates; `team context` reads it all back, read-only.
  </Card>
  <Card title="Dependency-Gated Tasks" icon="list-format">
    Tasks carry status, priority, owner, and dependencies. Work stays `planned` until its dependencies complete, and concurrent claims are arbitrated by the database — not by luck.
  </Card>
  <Card title="Auditable by Default" icon="open-book">
    Every transition lands in an append-only event stream, alongside Git-aware checkpoints, immutable decision records, and full-text search across all of it.
  </Card>
  <Card title="Per-Task Worktree Isolation" icon="code-branch">
    Bind a Git worktree to a task so parallel agents on parallel branches never collide, and context resolves from the directory an agent stands in.
  </Card>
  <Card title="AST Dependency Graph" icon="puzzle">
    Scans imports into a file-level dependency graph, exportable as Mermaid/DOT/ASCII, so agents reason about blast radius instead of hallucinating cross-file assumptions.
  </Card>
  <Card title="Presets, Skills & Personas" icon="setting">
    Install workflow SOPs, coding rules, and agent personas into `.carryctx/` — conventions ship with the repository instead of living in prompts.
  </Card>
  <Card title="Lifecycle Cleanup & Evidence" icon="approve-check-circle">
    v0.11.0 (since v0.8) records cleanup requests and policies, reconciles safe worktree removal, and preserves audit and analytics evidence through release.
  </Card>
  <Card title="Agent Analytics" icon="analytics">
    `carryctx stats` reports sessions, throughput, checkpoints, and blockers per agent — real numbers for tuning your harness, computed entirely locally.
  </Card>
</CardGrid>

## Why not just Markdown notes?

<div class="ctx-reveal">
<CardGrid>
  <Card title="Structured, not prose" icon="list-format">
    Tasks, checkpoints, and decisions are queryable rows, not paragraphs an agent has to re-parse from scratch every session.
  </Card>
  <Card title="Git-native truth" icon="code-branch">
    Branch, HEAD, dirty state, and diffs are captured automatically. Never manually transcribed, never stale.
  </Card>
  <Card title="Built for hand-off" icon="random">
    Any agent, in any worktree, resumes with `carryctx resume`. No chat history to re-read, no context to rebuild.
  </Card>
</CardGrid>
</div>

## How it works

<div class="ctx-reveal">
<Steps>
  1. **Set the contract.** `carryctx init` records the project configuration and creates state at `<git-common-dir>/carryctx/state.sqlite`.
  2. **Plan the work.** Create tasks, dependencies, scopes, and a ready queue; let the external harness define and run validation, then record the evidence in checkpoints.
  3. **Define roles and teams.** Register humans, commanders, and role-specialized subagents; the external harness decides scheduling.
  4. **Run sessions in worktrees.** Bind worktrees, claim tasks, and record progress and Git-aware checkpoints.
  5. **Handoff and review.** Transfer ownership explicitly, review the work, and preserve decisions and verification results.
  6. **Reconcile and release.** v0.11.0 (since v0.8) cleanup policies safely retry or block worktree removal; audit events and analytics provide release evidence.
</Steps>
</div>

## See it in action

<div class="ctx-reveal">
<Tabs>
  <TabItem label="Initialize">
    ```bash
    carryctx init
    carryctx agent register --name my-agent --provider user
    ```
  </TabItem>
  <TabItem label="Work">
    ```bash
    carryctx task create --title "Ship the exporter"
    carryctx task claim CTX-0001
    carryctx progress todo "Wire up the CSV writer"
    ```
  </TabItem>
  <TabItem label="Checkpoint">
    ```bash
    carryctx checkpoint \
      --done "Implemented CSV writer" \
      --remaining "Add streaming support"
    ```
  </TabItem>
  <TabItem label="Resume">
    ```bash
    carryctx resume
    # Task CTX-0001, last checkpoint 12m ago,
    # branch feature/csv-export, 2 files dirty.
    ```
  </TabItem>
  <TabItem label="Team">
    ```bash
    carryctx team create --name payments-squad --commander commander-1
    carryctx team member add payments-squad --agent backend-1 --role backend
    carryctx task team set CTX-0001 --team payments-squad
    carryctx team context payments-squad --agent-for backend-1
    ```
  </TabItem>
  <TabItem label="Serve over MCP">
    ```bash
    carryctx mcp
    # Six tools over stdio: task_manager, progress_tracker,
    # decision_logger, graph_explorer, context_manager,
    # project_admin.
    ```
  </TabItem>
</Tabs>
</div>
