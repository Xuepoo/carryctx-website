## CarryCtx 是什么

<p class="ctx-lede ctx-reveal">
  CarryCtx 是位于仓库与每一位 Agent / 协作者之间的<strong>持久化项目状态与控制层</strong>。三个关键词定义它。
</p>

<div class="ctx-reveal">
<CardGrid>
  <Card title="持久化状态" icon="document">
    一份位于 `<git-common-dir>/carryctx/state.sqlite` 的 SQLite 文件，由所有关联 Worktree 共享。任务、依赖、会话、检查点、交接、决策、事件与统计都是可查询的行记录——不是每次都要重读的流水账。
  </Card>
  <Card title="全生命周期" icon="random">
    从 `init` 与依赖化规划，到角色与团队、Worktree 绑定的会话、进度与检查点、交接到评审，再到清理、协调与发布证据——一个控制面覆盖完整交付链路。
  </Card>
  <Card title="可携带的离线状态" icon="approve-check-circle">
    默认完全本地、完全离线。无云服务、无账号、无网络往返。通过 `carryctx export` / `import`（`ctxpack`）搬运状态，传输交给 Git、SSH 或你选择的任意外部工具。
  </Card>
</CardGrid>
</div>

<div class="ctx-reveal">

### 它不是什么

<CardGrid>
  <Card title="不是 Agent Harness" icon="error">
    CarryCtx 不负责拉起、调度或分发 Agent 进程。执行归外部 harness 掌管——CarryCtx 只持久化这些进程据以协作的状态。
  </Card>
  <Card title="不是 Claude Code 替代品" icon="error">
    它与 Agent 无关。Claude Code、Codex、OpenCode、Copilot 或终端前的人类，都使用同一套 CLI 与 stdio MCP 接口。
  </Card>
  <Card title="不是云端同步服务" icon="error">
    无托管状态、无遥测、无强制账号。状态以本地文件形式由你掌控与搬运。
  </Card>
  <Card title="不是 TODO List" icon="error">
    依赖门控的任务、CAS 安全的认领与交接、Git 感知的检查点与只追加事件日志——远比清单更丰富的模型。
  </Card>
</CardGrid>
</div>

## 核心特性

<p class="ctx-lede ctx-reveal">
  CarryCtx 为 AI 编码 Agent 与人类协作者管理软件交付的完整生命周期。它把聊天记录天生装不下的项目契约、计划、依赖、角色、会话、进度、评审、清理决策与发布证据，保存为一份本地、基于 Git 的状态模型。
</p>

<CardGrid stagger>
  <Card title="100% 离线 & 本地" icon="approve-check-circle">
    状态存放在 `<git-common-dir>/carryctx/state.sqlite`，由关联 Worktree 共享。不需要云服务、账号或网络往返。
  </Card>
  <Card title="持久化 Agent 团队" icon="bars">
    一位指挥官加上角色化的子 Agent，像其他事实一样被持久保存。交接经由状态机与 CAS 更新推进；`team context` 以只读方式读回全貌。
  </Card>
  <Card title="依赖门控的任务" icon="list-format">
    任务自带状态、优先级、归属和依赖。依赖未完成，工作就停留在 `planned`；并发认领由数据库仲裁——而不是碰运气。
  </Card>
  <Card title="天然可审计" icon="open-book">
    每一次状态转换都会落入只追加的事件流，旁边是具备 Git 感知的检查点、不可变的决策记录，以及覆盖这一切的全文搜索。
  </Card>
  <Card title="按任务隔离 Worktree" icon="code-branch">
    把 Git Worktree 绑定到任务，让并行分支上的多个 Agent 互不干扰；上下文根据 Agent 所在的目录自动解析。
  </Card>
  <Card title="AST 依赖图谱" icon="puzzle">
    扫描 import 语句构建文件级依赖图谱，可导出为 Mermaid/DOT/ASCII，让 Agent 推算改动波及面，而不是幻觉式地假设跨文件关系。
  </Card>
  <Card title="预设、技能与人格" icon="setting">
    把工作流 SOP、编码规则和 Agent 人格安装进 `.carryctx/`——约定跟着仓库走，而不是散落在 prompt 里。
  </Card>
  <Card title="生命周期清理与证据" icon="approve-check-circle">
    v0.8 记录清理请求与策略，安全协调 Worktree 删除，并在发布前保留审计与统计证据。
  </Card>
  <Card title="Agent 数据统计" icon="analytics">
    `carryctx stats` 按 Agent 汇总会话数、产出、检查点和阻塞项——用真实数字调优你的 harness，全程本地计算。
  </Card>
</CardGrid>

## 为什么不直接用 Markdown 笔记？

<div class="ctx-reveal">
<CardGrid>
  <Card title="结构化，而非流水账" icon="list-format">
    任务、快照与决策都是可查询的结构化数据，而不是每次开新会话都要重新阅读的一大段文字。
  </Card>
  <Card title="Git 原生的真相来源" icon="code-branch">
    分支、HEAD、脏工作区状态与 Diff 全部自动采集，无需手动誊写，也不会过期。
  </Card>
  <Card title="为交接而设计" icon="random">
    任何 Agent、在任何 Worktree 中，执行 `carryctx resume` 即可恢复——无需翻阅聊天记录，无需重建上下文。
  </Card>
</CardGrid>
</div>

## 工作原理

<div class="ctx-reveal">
<Steps>
 1. **建立契约。** `carryctx init` 写入项目配置，并在 `<git-common-dir>/carryctx/state.sqlite` 创建共享状态。
  2. **规划工作。** 创建任务、依赖、范围与就绪队列；验证标准和执行由外部 harness 负责，再把验证证据记录到检查点中。
 3. **定义角色和团队。** 注册人类、指挥官与角色化子 Agent；进程调度由外部 harness 决定。
 4. **在会话和 Worktree 中执行。** 绑定 Worktree、认领任务，记录进度与 Git 感知的检查点。
 5. **交接与评审。** 显式转移负责人，完成评审，并保存决策与验证结果。
 6. **协调清理并发布。** v0.8 清理策略会安全重试或阻塞 Worktree 删除；审计事件与统计为发布提供证据。
</Steps>
</div>

## 实际效果

<div class="ctx-reveal">
<Tabs>
  <TabItem label="初始化">
    ```bash
    carryctx init
    carryctx agent register --name my-agent --provider user
    ```
  </TabItem>
  <TabItem label="开始工作">
    ```bash
    carryctx task create --title "上线导出功能"
    carryctx task claim CTX-0001
    carryctx progress todo "接入 CSV 写入器"
    ```
  </TabItem>
  <TabItem label="保存快照">
    ```bash
    carryctx checkpoint \
      --done "实现了 CSV 写入器" \
      --remaining "增加流式写入支持"
    ```
  </TabItem>
  <TabItem label="恢复进度">
    ```bash
    carryctx resume
    # → 任务 CTX-0001，最近一次快照 12 分钟前，
    #   分支 feature/csv-export，2 个文件未提交。
    ```
  </TabItem>
  <TabItem label="团队协作">
    ```bash
    carryctx team create --name payments-squad --commander commander-1
    carryctx team member add payments-squad --agent backend-1 --role backend
    carryctx task team set CTX-0001 --team payments-squad
    carryctx team context payments-squad --agent-for backend-1
    ```
  </TabItem>
  <TabItem label="以 MCP 服务">
    ```bash
    carryctx mcp
    # 六个 stdio 工具：task_manager、progress_tracker、
    # decision_logger、graph_explorer、context_manager、
    # project_admin。
    ```
  </TabItem>
</Tabs>
</div>
